# Complaint coverage

This map treats the supplied Theo Browne analysis as product input. Its quotes,
dates, vendor claims, and accounts of GitHub behavior were not independently
checked. The implementation addresses the reproducible workflow concerns
below. Mocked tests and local Git fixtures do not prove behavior against a live
GitHub account or another terminal platform.

| Concern | Current source behavior | Focused evidence | Remaining limit |
| --- | --- | --- | --- |
| Word deletion, queued input, and cancellation | `src/utils/prompts.ts` uses the buffered line reader in `src/utils/line-input.ts`; queued and partial text survives transitions, and EOF or Ctrl-C releases input ownership. | `tests/prompt-input.test.ts`; a native macOS PTY run passed ESC-DEL word deletion and Ctrl-C with exit 130. | The unit test does not cover every keyboard mapping. Linux and Windows terminal input still needs native checks. |
| Repo wizard asks for known values | `src/services/publication.ts` inspects the local Git root, name, branches, and remotes. `src/commands/repo.ts` uses the inferred private repo, `origin`, and current branch plan with one confirmation by default. | `tests/publication.test.ts`, `tests/publication-cli.test.ts`. | GitHub inspection and writes still depend on the installed `gh`, authentication, permissions, and network. |
| Prompt count and network pauses | Publication plans collect unresolved local choices before confirmation and mutation. Dry-run reports the plan without writing. | `tests/publication.test.ts`, `tests/publication-cli.test.ts`; `tests/prompt-input.test.ts` checks queued answers across prompts. | No latency benchmark establishes GitHub response time. Remote inspection can still wait on GitHub. |
| Redundant remote and push questions | The inferred plan uses `origin` and pushes the current branch. Explicit visibility, source, remote, and push flags override defaults; conflicting or non-GitHub remotes require resolution. | `tests/publication.test.ts`, `tests/publication-cli.test.ts`. | Mocked `gh` and local bare Git do not establish live account behavior. |
| PR creation with no remote | `src/commands/pr-create.ts` calls the shared publication service. It validates base and head before writes, then creates the repo, adds the remote, pushes base and head, and opens the PR. `commit --pr` uses the same workflow after explicit local commit input. | `tests/publication-cli.test.ts`, `tests/commit-publication.test.ts`. | Live GitHub authorization, repository rules, branch protection, and API behavior remain unverified. |
| PR screenshots and videos | `src/services/github/attachments.ts` preflights PNG, GIF, JPG, JPEG, SVG, WEBP, MP4, MOV, and WEBM. It allows up to 50 files, with local limits of 10 MiB per image and 100 MiB per video. It detects native support from installed `gh` help, allows a configured uploader only for verified public repos, and preserves the resource URL on partial failure. GitHub documents `--attach` in its [CLI attachment guide](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli) and [`gh pr create` manual](https://cli.github.com/manual/gh_pr_create). | `tests/attachments.test.ts` checks WEBP validation, the 50-file cap, capability detection, private fallback refusal, and partial results. Create-flow coverage is in `tests/publication-cli.test.ts`. | GitHub docs set video limits by account plan: 10 MB for free plan repos and 100 MB for paid plan repos, with eligibility requirements above 10 MB. The ggh 100 MiB local ceiling does not guarantee server acceptance. GitHub's documented image list does not name WEBP. Live upload and private access remain unverified. |
| Stacked branches and recovery | `src/services/git/stack.ts` and `src/commands/stack.ts` store parent relationships, restack locally, support `--continue` and `--abort`, retain recovery tips, and use force-with-lease for explicit submission when replacing a remote tip. | `tests/stack-recovery.test.ts`. | Fixtures use local Git and mocked GitHub calls. They do not prove live PR ordering or account permissions. |
| One commit-to-PR flow | `commit --pr`, `pr create`, and repo creation share `src/services/publication.ts`; reports include completed and remaining steps for partial outcomes. | `tests/commit-publication.test.ts`, `tests/publication-cli.test.ts`. | Local acceptance passed; live GitHub behavior remains unverified. |
| Agent-friendly input and JSON | Explicit `ggh git`, `ggh gh`, and `ggh --` preserve native arguments and process results. Unknown commands do not become Git commands. JSON results cover dry-run, missing input, cancellation, and partial completion on covered paths. | `tests/passthrough.test.ts`, `tests/json-contract.test.ts`, `tests/json-empty-success.test.ts`, `tests/json-mutations.test.ts`. | The command audit and full source suite passed. Flag combinations beyond the regressions still need testing during the beta. |
| PR and CI smartlog | `ggh stack list --remote` joins local branch relationships with PR review and CI. Plain `ggh stack list` stays offline. The remote view limits work to 25 branches, runs at most five lookups concurrently, and retains local branches with an explicit unavailable status when GitHub cannot answer. | `tests/stack-recovery.test.ts` checks offline local reads, PR review and CI data, and unavailable remote results without losing branches. | The full source suite passed, including the expanded recovery, view, race, and target checks. GitHub calls were mocked; live auth and rate limits remain unverified. |
| Provider usage reporting | `src/services/ai` extracts usage only when a provider reports reliable values. Operation records accept validated token and cost fields and leave absent values absent. | `tests/ai-usage.test.ts`, `tests/operations.test.ts`. | Provider coverage is incomplete. Unknown token counts and costs stay unknown; no transcript-length estimate is made. |
| Agent provenance and private records | `src/services/operations.ts` records structured operation metadata and revision links. `ggh operation evidence` associates a local file by path and revision without copying or checking it. `GGH_NO_RECORDS=1` disables records. | `tests/operations.test.ts`; publication body exclusion in `tests/publication-cli.test.ts`. | Evidence references do not verify file contents. Raw prompts, transcripts, and source content are not stored by default. |
| Stale tool guidance | `ggh config doctor` checks for Git and `gh`, reports their local versions, probes six native attachment flags, and checks installed provider CLI versions and capabilities. It does not check authentication or model access. | `src/commands/config.ts` and the new `tests/doctor.test.ts` cover versions, attachment flags, missing required tools, optional AI tools, and no-auth probe behavior. | Doctor source tests and actual local version/help probes passed. Authentication, service health, model access, and future CLI behavior need separate live checks. The tool does not write agent memory workarounds. |
| Community backlash and vendor comparisons | Historical frustration and comparisons with other hosting products are not runtime requirements. This project implements local defaults and GitHub workflows it can control. | No behavior test applies. | The supplied accounts and vendor claims remain unverified. GitHub uptime and other tools' server behavior are outside this CLI's control. |

The focused files listed here are regression targets. The
[local acceptance receipt](verification/2026-10-14-local-acceptance.md) records
macOS integration and package checks. The subsequent
[test audit](verification/2026-10-14-test-audit.md) retained all 50 source suites
and passed 500 source tests and 71 native cases. Linux, Windows, and separately
authorized live GitHub acceptance remain launch checks.
